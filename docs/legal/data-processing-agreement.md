# Data processing agreement (GDPR Article 28) — template

English translation of [contrat-sous-traitance.fr.md](contrat-sous-traitance.fr.md),
for information. It was written for operators established in France; adapt it
to your jurisdiction and have it reviewed. It is not legal advice.

**Status**: template written on 2026-10-21 for `specs/021-legal-pages`
(research R10). It binds the **operator** of a Trefle installation (processor)
and the **owner of a domain** served by that installation (controller).

## 1. Purpose

The Processor provides the Controller with the Trefle service for the domain
[domain]: creation and hosting of pages, contact forms, recording of
requests and consents, sending of confirmation e-mails, page tests and their
measurement. This agreement sets the conditions under which it processes, on
the Controller's behalf, the personal data needed for this service.

## 2. Description of the processing

| | |
|---|---|
| Nature | Collection through forms, recording, storage, consultation, export, erasure; sending of transactional e-mails; measurement of page tests |
| Purposes | Receive and manage contact requests from the domain's visitors; prove their consent; compare versions of pages |
| Data subjects | The domain's visitors, people who submit the form |
| Data | Form fields (identity, contact details, message), page and date of submission, proof of consent (text, date, IP address, browser), view number and page version seen during a test |
| Duration | That of the service contract; retention: [24 months] for requests, 30 days after a test ends for test data |

## 3. Obligations of the Processor

The Processor undertakes to:

1. process the data only for the purposes above and on documented
   instructions from the Controller, including for transfers outside the
   European Union; if it considers that an instruction infringes the
   regulations, it informs the Controller immediately;
2. guarantee the confidentiality of the data and ensure that the persons
   authorised to process it are bound by confidentiality;
3. implement the security measures described in Annex 2;
4. use only the sub-processors listed in Annex 1; inform the Controller of
   any addition or replacement at least [30] days in advance, the Controller
   being entitled to object; impose on each of them the same obligations as
   those of this agreement;
5. help the Controller respond to requests from data subjects exercising
   their rights (access, rectification, erasure, objection, restriction,
   portability), in particular through the tool's export and erasure
   functions;
6. notify the Controller of any personal data breach within [48 hours] of
   becoming aware of it, with the information the Controller needs for its own
   notification to the supervisory authority (the CNIL in France);
7. help the Controller with its data protection impact assessments and the
   prior consultation of the supervisory authority where needed;
8. at the end of the service, as the Controller chooses, return the data to it
   (export) and then delete it and its copies, unless the law requires them to
   be kept;
9. make available the information needed to demonstrate compliance with this
   agreement and allow audits, including inspections, by the Controller or an
   auditor it appoints, [once a year] unless an incident occurs.

## 4. Obligations of the Controller

The Controller undertakes to: give the Processor the information it needs
(identity, data protection contact, texts specific to the domain); inform
data subjects (the domain's privacy policy, generated by the tool, must be
reviewed); ensure compliance with the GDPR throughout the processing;
supervise the processing.

## 5. Duration

This agreement takes effect on signature and lasts as long as the service.

## Annex 2 — Security measures

- Access to the administration limited to active members, behind Cloudflare
  Access (code by e-mail) and two-factor authentication; the server checks
  the access token.
- Server reachable only through Cloudflare's network (firewall and client
  certificate); TLS encryption end to end.
- Secrets encrypted in the code repository; daily database backups.
- Log of sensitive actions (exports, erasures, sign-ins).
- Retention periods applied automatically (daily purge).
- Page test data without any tracker on visitors' devices.
